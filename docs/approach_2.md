# 构想二：逐乐器"重演"法

## 核心理念

> 受 B 站"钢琴还原名场面"启发：不是从混合信号中"滤出"目标乐器，而是**用目标乐器重新演奏"最像它"的部分**。

---

## 1. 思路拆解

### 1.1 原始过程

1. 取一段混合音频（如"鸡汤来了"名场面）
2. 用钢琴完整"演奏"一遍（即让钢琴去覆盖/解释整段音频）
3. 对结果逐片段检查："这段钢琴出声像不像原素材里的钢琴部分？"
4. 保留"像"的片段，丢弃"不像"的
5. 对每种乐器重复（钢琴、小提琴、贝斯、小号……）
6. 把所有乐器保留的片段拼接成完整分离结果

### 1.2 形式化

$$x_i = \text{select}\big( f_i(y), \text{conf}(f_i(y)) > \theta \big)$$

其中：
- $y$ = 混合音频
- $f_i$ = 以第 $i$ 种乐器为条件的"还原"模型（从混合 → 该乐器版本）
- $\text{conf}(\cdot)$ = 置信度评估函数
- $\theta$ = 保留阈值
- $\text{select}$ = 保留高置信度片段

### 1.3 这本质上是什么？

这个方法其实是 **生成式声源分离（generative source separation）** 的一种形式，近年在学术界有相关探索（如 [Universal Sound Separation](https://arxiv.org/abs/1905.03379) 中的某些思路，以及 Google 的 [SepFormer](https://arxiv.org/abs/2010.13154) 等）。

它和构想一的核心区别：

| 维度 | 构想一（波形分解） | 构想二（逐乐器重演） |
|------|-------------------|-------------------|
| 范式 | 分析式（Analysis） | 生成式（Generation） |
| 对混合信号的处理 | 分解它 | 以它为条件去"生成匹配它"的版本 |
| 输出确定性 | 确定性的掩码 → iSTFT | 生成模型可能每次输出略有不同 |
| 对训练数据的要求 | 需要多轨数据 | 既需要多轨数据，又需要"乐器 solo + 混合"配对 |
| 优势 | 稳定、可解释、效果好 | 可能更灵活、能处理未见过的乐器组合 |
| 弱点 | 对罕见乐器组合泛化差 | 可能存在"幻觉"（生成不存在的内容） |

## 2. 两种具体的实现路径

### 2.1 路径 A：基于转录—合成（Transcription-to-Synthesis）

```
混合音频 y
    │
    ▼
[多乐器音高转录模型]
同时检测：什么乐器、什么音高、什么时间发声
    │
    ▼
各乐器的事件序列（音符级）
    钢琴: [(C4, 0.0s, 0.5s), (E4, 0.5s, 1.0s), ...]
    小提琴: [(G4, 0.2s, 0.8s), ...]
    │
    ▼
[逐乐器合成]
每个乐器用高保真音源库（或可微分合成器）重新渲染
    │
    ▼
x₁(t), x₂(t), ..., x_c(t)
这就是你所说的"用某个乐器还原名场面"
```

这个路径的核心是 **自动音乐转录（Automatic Music Transcription, AMT）**——让模型听混合音频，输出"什么乐器在什么时间弹了什么音"。

如果转录准确，合成环节用高质量音源库，结果会很干净——因为输出不是从噪声中"滤"出来的，而是**新生成的**。

**优势**：可以处理带噪数据、可以输出 MIDI 乐谱（顺便实现了乐谱还原）
**劣势**：转录本身很难（多乐器同时演奏时，分离 + 识别音高的复杂度很高）

#### 你对这个路径的修改建议

你强调"删去不符合他的片段的声音"——这个直觉非常关键：

- 一个钢琴模型还原全程，但某些片段钢琴根本没出声，这时模型就会"硬弹"一些不合理的音
- **解决方案**：用逐帧的"声源活动检测"（sound activity detection），只保留钢琴确实在演奏的片段

```python
def frame_selective_separation(y, instrument_model, activity_model, threshold=0.3):
    """
    y: 混合音频
    instrument_model: 该乐器的"重演"模型
    activity_model: 检测该乐器是否在活动的模型
    """
    # 模型先完整"重演"一遍
    full_render = instrument_model(y)

    # 逐帧检测该乐器是否真的在发声
    activity = activity_model(y)  # per-frame 0~1 的置信度

    # 只保留置信度高的帧
    mask = activity > threshold
    output = full_render * mask[:, None]  # 广播到所有音频通道

    return output
```

### 2.2 路径 B：基于音色转换（Timbre Transfer / Voice Conversion 思路）

```
混合音频 y
    │
    ▼
[特征解耦编码器]
将音频分解为：
  - 内容特征（音高、节奏、旋律轮廓）
  - 音色特征（乐器种类、演奏法）
    │
    ▼
[音色条件重合成]
保留内容特征，替换音色特征为目标乐器的音色
    │
    ▼
用钢琴音色重合成"内容" → 得到"钢琴版"音频
用小提琴音色重合成"内容" → 得到"小提琴版"音频
```

这个路径更接近你原文描述的过程，但技术难度更高（特征解耦目前还是开放问题）。

## 3. 构想二在整体架构中的位置

### 构想二作为"副驾驶"

构想一（掩码法）作为主力模型的**合理性很好，因为 DEMUCS 等架构已经验证了这条路走得通**。

但构想二可以做以下事情：

### 3.1 作为后处理/修复模块

掩码法分离的结果往往有一些问题：
- **乐器和音（leakage）**：钢琴的尾音留到了小提琴轨
- **伪影（artifacts）**：iSTFT 的相位近似带来金属声

构想二可以在这些有问题的片段上"重演"——用小提琴音色重新生成应该属于小提琴的部分，覆盖有问题的分离结果。

### 3.2 作为置信度引导

```
┌─ 构想一 ──────┐    ┌─ 构想二 ──────┐
│ 掩码法分离结果 │ →  │ 对该片段用x乐器 │
│ (可能有伪影)   │    │ "重演"一遍     │
└───────────────┘    └───────────────┘
                          │
                     ┌────┴────┐
                     ↓         ↓
                构想一结果    构想二结果
                （较低SDR）  （较高SDR）
                     │         │
                     └────┬────┘
                          ↓
                选择该片段SDR更高的版本
```

### 3.3 作为 Mid-Level 的替代方案

目前几个流行的音源分离模型试用下来，你可能会发现它们对一些情况处理得不好：比如罕有乐器组合、电子音乐、非西方音乐。这个时候，构想二可以提供一个完全不同的分离视角——**就像两个不同的乐评人互相校核**。

这个整体方案中，你不需要二选一——把构想二作为一个补充模块加入管道中，这样整体的鲁棒性会大大增强。

## 4. 实现"钢琴还原"的 Mini 项目

这是你立刻可以动手尝试的一个小实验——不需要 GPU、不需要大量数据：

```python
import librosa
import numpy as np
import soundfile as sf
from scipy import signal

def simple_piano_resynthesis(y, sr, f0_estimates):
    """
    一个极度简化的"钢琴重演"演示。
    真正的实现需要深度学习模型，这里仅展示概念。
    
    y: numpy array, 混合音频波形
    f0_estimates: array, 逐帧估计的基频
    """
    output = np.zeros_like(y)
    hop_length = 512

    for t, f0 in enumerate(f0_estimates):
        if f0 > 0:  # 该帧有音高
            # 生成该基频的"钢琴音"（简化：纯正弦波 + 泛音）
            n_samples = hop_length
            t_arr = np.arange(n_samples) / sr
            # 钢琴的典型泛音结构
            harmonics = [1, 2, 3, 4, 5, 6, 8]
            amplitudes = [1, 0.6, 0.3, 0.1, 0.05, 0.02, 0.01]
            frame = np.zeros(n_samples)
            for h, a in zip(harmonics, amplitudes):
                frame += a * np.sin(2 * np.pi * f0 * h * t_arr)
            # 加指数衰减包络（模拟钢琴延音）
            envelope = np.exp(-t_arr * 5)
            output[t * hop_length : t * hop_length + n_samples] = frame * envelope

    return output
```

这只是一个概念演示。真实的"钢琴重演"需要：
- 一个预训练的**多乐器音高检测模型**（如 Google 的 [SPICE](https://arxiv.org/abs/2004.00944) 或 [Basic Pitch](https://github.com/spotify/basic-pitch)）
- 一个**可微分合成器**（如 [DDSP](https://github.com/magenta/ddsp)）或高质量音源库
- 一个**置信度评估器**（判断生成的片段是否合理）

## 5. 构想二的独特价值

有一类问题构想一比构想二更难处理：

| 场景 | 构想一的问题 | 构想二的优势 |
|------|-------------|-------------|
| 混合中有两个音高相近的乐器（如两把吉他） | 频谱重叠，掩码法难以分开 | 可以用不同音色的合成器"重新演奏"各自的音高 |
| 混合中有非稳态噪声 | 噪声会和乐器一起被"滤出" | 生成模型不会生成噪声 |
| 想要输出 MIDI 乐谱 | 需要额外做 AMT | 转录→合成路径天然产出 MIDI |

> **构想二的最佳应用方式**：不是替代构想一，而是作为互补模块，在构想一表现不佳的片段上补充分离质量。

---

## 6. 结合两种构想的完整管道

你的两段思考结合起来，就已经非常接近当前学术界的主流框架了：

```
                   混合音频 y
                        │
               ┌────────┴────────┐
               ↓                 ↓
         构想一（掩码法）    构想二（生成法）
         U-Net 预测掩码     AMT + 合成 / 音色转换
               │                 │
               │          ┌──────┘
               ↓          ↓
         初步分离结果     "重演"结果
               │                 │
               └────────┬────────┘
                        ↓
              [融合决策模块]
              比较每帧两种方法的置信度
              选优 / 加权平均
                        │
                        ↓
                  最终分离结果
              x₁(t), x₂(t), ..., x_c(t)
```

这实际上是一种 **集成学习方法（ensemble learning）**——两种不同范式的方法互相校验和补充，往往比单独使用任何一种都稳定。

---

## 7. 一句话总结

> **构想二的核心**：不是从混合中"提纯"乐器，而是让每个乐器"重新演奏一遍混合音频中属于它的部分"，再筛选出置信度高的片段拼起来。它和构想一是互补关系——前者是分析式分离，后者是生成式分离，两者结合比单独使用更鲁棒。
