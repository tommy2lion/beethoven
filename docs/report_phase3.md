## 二、策略：教师-学生学习

### 2.1 为什么不用 MUSDB18？

MUSDB18 是声源分离的标准数据集（150 首多轨歌曲），但下载地址（Zenodo）在中国无法访问。

**替代方案：教师-学生蒸馏**

```
任何一首歌.mp3
      │
      ▼
┌─────────────┐     ┌──────────────────┐
│ Demucs (老师)│────→│ 4 轨分离结果      │
│ SOTA 模型    │     │ (vocals/bass/    │
│             │     │  drums/other)     │
└─────────────┘     └────────┬─────────┘
                             │ 作为训练标签
                             ▼
                    ┌──────────────────┐
                    │ U-Net++ (学生)    │
                    │ 学习模仿 Demucs   │
                    └──────────────────┘
```

优势：
- **不需要任何数据集下载**，用你已有的歌就能训
- 学生模型可以比老师更轻量、更快
- 可以针对特定音乐类型微调

### 2.2 数据管线改进

| 改进点 | Phase 2 | Phase 3 |
|--------|---------|---------|
| 数据来源 | 4 段合成音频 | 真实歌曲 |
| 处理方式 | 整曲训练 | **6 秒切片**（解决内存问题） |
| 乐器数 | 3（钢琴/小提琴/贝斯） | **4（人声/贝斯/鼓/其他）** |
| 输出文件 | 自动生成 | 由 Demucs 老师提供 |

## 三、模型架构升级

### 3.1 U-Net++ 设计

| 组件 | Phase 2 U-Net | Phase 3 U-Net++ |
|------|:------------:|:---------------:|
| 基础通道数 | 16 | **24** |
| 卷积模块 | 普通 Conv2D | **ResBlock（残差连接）** |
| 网络深度 | 4 级 | 4 级 |
| 参数量 | **194 万** | **658 万** (~3.4×) |
| 输出乐器 | 3 | **4** |

### 3.2 关键改进：ResBlock

```
Phase 2: Conv → BN → ReLU → Conv → BN → ReLU
Phase 3: Conv → BN → ReLU → Conv → BN → +输入 → ReLU
                                   ↑
                             残差连接（梯度直达）
```

残差连接让梯度可以直接流向浅层，解决深层网络训练困难的问题。

### 4.3 与 Demucs 老师对比

在光辉岁月上测试，对比学生（U-Net++）和老师（Demucs）的输出音量：

| 乐器 | Demucs (老师) | U-Net++ (学生) | 接近程度 |
|------|:-----------:|:-------------:|:-------:|
| **Vocals** 🎤 | RMS 0.075 | RMS **0.059** | **79%** |
| **Bass** 🎸 | RMS 0.043 | RMS **0.042** | **98%** |
| **Drums** 🥁 | RMS 0.044 | RMS **0.029** | **66%** |
| **Other** 🎵 | RMS 0.054 | RMS **0.057** | **105%** |

**仅用 17 段、1 首歌训练，学生模型已经达到老师 66-105% 的水平！**

贝斯几乎完美复现（98%），说明低频乐器最容易学习。
鼓稍弱（66%），因为打击乐的瞬态结构更难捕捉。

## 六、局限与 Phase 4 方向

### 当前局限

1. **只训练了 1 首歌**——17 段切片太少了
2. **学生不可能超过老师**——U-Net++ 上限就是 Demucs 的质量
3. **鼓的建模偏弱**——打击乐的瞬态需要更多训练数据
4. **CPU 训练**——658 万参数在 CPU 上训练较慢

### Phase 4 探索方向

1. **更多训练数据**：加入多首歌曲，让学生模型见过更多变体
2. **构想二探索**：实现你最初的"逐乐器重演"想法（生成式分离），这能超越 Demucs
3. **对抗训练**：直接让我们的模型和 Demucs 比赛，而不只是模仿
4. **细分乐器**：把"Other"进一步拆分为吉他、钢琴、键盘等
5. **交互式 Web App**：用 Gradio 封装，上传歌曲→选择乐器→听到分离
