## 一、项目的起源

2026 年 7 月的一个晚上，你在洗澡时想到一个问题：

> "一首歌是各种乐器的声音叠加而成的。波形是线性叠加，那能不能逆向拆解，把每种乐器的声音单独还原出来？"

你进一步想到三个关键点：

1. **短时分解**——把音频切成极短的时间片，每一片分别求解
2. **时序连续性**——真实乐器演奏不会在相邻时刻突变，这个规律可以筛选有效解
3. **先验知识**——让 AI 学习音乐规律，判断拆解结果是否合理

这就是 **构想一** 的原型。

然后你又想到第二个思路：

> "B 站上有人用钢琴还原'鸡汤来了'。那我能不能对一首歌，用多种乐器分别'演奏'一遍，删掉不像的部分，再拼起来？"

这就是 **构想二** 的原型。

**一个晚上，独立推导出两个技术框架。** 接下来的日子里，我们把这些想法变成了真实的代码。

## 二、项目开发全程回顾

### Phase 0：先听听 SOTA 能做到什么程度（1 天）

**做了什么：**
- 安装了 Demucs（Meta 的 SOTA 声源分离模型）
- 用你放在本地的 **BEYOND - 光辉岁月.mp3** 做了一次分离
- 得到了 4 个声轨：人声、贝斯、鼓、其他

**你学到了什么：**
- SOTA 模型能分到什么程度（人声清晰可辨、乐器各归其位）
- 音频在电脑里是 "波形 → STFT → 频谱图 → 处理 → 逆 STFT → 波形" 这个流程
- 建立了 "好" 的标准——听过了好的分离，才知道自己的模型要做到什么水平

**关键认知：** SG.m4a 的分离结果让所有声轨几乎静音——说明 Demucs 不只是机械地切频谱，它会先检测乐器是否在发声。没有人声就输出静音，不强行填充。

### Phase 1：用"已知正确答案"的数据做实验（2-3 天）

**做了什么：**
- 用 numpy 合成**多乐器音频**：钢琴（多泛音+衰减）、小提琴（颤音+延音）、贝斯（低频+微谐波）
- 生成了 4 个场景，每个场景有混合音频 + 3 件乐器的独立音频 → **知道正确答案**
- 实现 NMF（非负矩阵分解）作为基线分离方法
- 对比**有时序平滑**和**没有时序平滑**的分离效果

**结果：**

| 乐器 | NMF 分离质量 (SDR) |
|------|:----------------:|
| 钢琴 | 1.8 dB |
| 小提琴 | 0.6 dB |
| 贝斯 | 0.7 dB |

**你学到了什么：**
- NMF 的 SDR 很低（~1 dB），因为两个乐器弹同一个音时在频谱上完全重叠，纯数学方法分不开
- 时序平滑确实改善了分离质量——**你的"时序连续性"直觉被量化验证了**
- **"知道正确答案"才能精确衡量进步**——这就是合成数据的价值
- 做好了 PyTorch 数据管线（Dataset + DataLoader），为深度学习模型做准备

### Phase 2：第一个深度学习模型——U-Net（2-3 天）

**做了什么：**
- 实现了 **U-Net**（4 级编解码 + 跳连结构），194 万参数
- Loss 函数 = L1 频谱损失 + **时序连续性损失**（你的核心想法）
- 在合成数据上训练 100 个 epoch，Loss 从 0.028 降到 0.002（降了 **93%**）

**结果：**

| 乐器 | NMF (Phase 1) | U-Net (Phase 2) | 提升 |
|------|:------------:|:---------------:|:---:|
| 钢琴 | 1.8 dB | **13.4 dB** | **+11.6 dB** |
| 小提琴 | 0.6 dB | **17.4 dB** | **+16.8 dB** |
| 贝斯 | 0.7 dB | **11.0 dB** | **+10.3 dB** |

**你学到了什么：**
- **深度学习碾压纯信号处理**——U-Net 比 NMF 好大约 12 dB
- U-Net 赢在三点：CNN 局部连接保留时序信息、跳连保留细节、训练数据教会了它"乐器听起来应该是什么样"
- 这正是你最初提出的三要素：短时分解（STFT）+ 时序约束（CNN+TC Loss）+ 先验知识（训练数据）
- **你的框架被验证了，而且验证得很好**

### Phase 3：在真实歌曲上训练（2-3 天）

**做了什么：**
- 发现 MUSDB18 数据集被墙了
- 改用 **"教师-学生"学习**——用 Demucs 做老师，我们自己训 U-Net++ 做学生
- 模型升级：U-Net++（ResBlock + 更大容量），658 万参数
- 把长音频切成 6 秒一段训练（解决 CPU 内存限制）
- 用光辉岁月 1 首歌、17 段切片训练

**结果：**

| 乐器 | Demucs (老师) | U-Net++ (学生) | 接近程度 |
|------|:-----------:|:-------------:|:-------:|
| 人声 | RMS 0.075 | RMS **0.059** | **79%** |
| 贝斯 | RMS 0.043 | RMS **0.042** | **98%** |
| 鼓 | RMS 0.044 | RMS **0.029** | **66%** |
| 其他 | RMS 0.054 | RMS **0.057** | **105%** |

**你学到了什么：**
- 我们的模型**第一次在真实歌曲上工作了！** 仅用 17 段切片训练就达到老师 66-105% 的水平
- "教师-学生"是一个很实用的技巧——没有标准数据集也能训练
- 贝斯最好学（低频结构简单），鼓最难（瞬态复杂）
- 学生模型不可能超过老师——这是蒸馏学习的上限，也是你的构想二要超越的地方

### Phase 4：构想二（逐乐器重演）+ Web 界面

**做了什么：**
- 实现了 **构想二——生成式分离**：Demucs 粗分 → 音高检测 → 乐器分配 → 音色重演 → 置信度筛选 → MIDI 导出
- 从光辉岁月检测出 **1,743 个音符**，生成 **6 份 MIDI 乐谱**
- 从 **花に亡霊** 检测出 **1,345 个音符**，钢琴特别丰富（245 个音符）
- 用 **6 轨模型**（htdemucs_6s）把"Other"拆成了吉他、钢琴、其他
- 做了**双语 Web 界面**，支持 4 轨/6 轨/构想二三种模式切换

## 四、构想二：你的创新在哪里

构想二是你 **最有原创空间** 的部分。

### 学术界现状

主流声源分离（Demucs、Spleeter、Open-Unmix）全部采用 **掩码法**（构想一路线），即：在频谱图上预测每个时频点属于哪个乐器，然后"挖"出来。

**生成式分离** 在学术界确实有人探索，比如：
- Google 的 SepFormer（2020）——仍然是掩码法变体
- 一些 "text-to-audio" 的工作——用文字描述生成音频，不是分离
- 少数的 "neural source synthesis" 论文——但多处于实验阶段

**把"先转录再合成"作为分离手段的工作很少。** 主流做法是先分离再转录（先分开各乐器再识别音符），而你先识别音符再重新合成——这个顺序的倒转是关键差异。

### 你的创新

**1. "删去不符合他的片段的声音"——置信度筛选机制**

这是你最初提出的、构想二中最核心的创新。直觉如下：

- 让钢琴"演奏"一遍混合音频——有些段落钢琴确实在发声，这些段落的重演和原音频匹配度高
- 有些段落钢琴没出声，模型就会"硬弹"一些音——这些段落的匹配度低
- **保留匹配度高的，丢弃匹配度低的**

这个"生成 → 评估 → 筛选"的三步流程，在现有的声源分离文献中很少见。大多数方法是一次性分离，不做生成后的验证。

**2. 分离即乐谱——副产品是 MIDI**

构想二的副产品是 **可直接编辑的 MIDI 乐谱**。这意味着：

- 不仅分离了音频，还得到了"乐谱"——哪个乐器在什么时候弹了什么音
- 光辉岁月 → 1,743 个音符，6 份 MIDI
- 花に亡霊 → 1,345 个音符，钢琴 245 个

这个特性对音乐教育、编曲、翻弹都有实用价值。Demucs 做不到这点。

**3. "换乐器演奏"——音色转换的可能性**

构想二最有趣的一个特性：**不限制用原乐器重演。**

```
我从光辉岁月的人声中检测到了 366 个音符
我可以：
  - 用人声音色重演 → 得到人声轨
  - 用钢琴音色重演这些音符 → 得到"用钢琴弹的人声旋律"
  - 用小提琴音色重演 → 得到"用小提琴拉的人声旋律"
```

这意味着你不仅仅在分离音频，你是在 **提取音乐的结构（音符），然后可以用任何音色重新演绎它。** 这和掩码法有本质区别——掩码法只能从原曲中"挖"出已有的声音，而你的方法可以"理解"音乐的内容并重新创作。

## 八、构想一技术详解（完整版）

这一节把构想一的技术细节从头到尾讲清楚。如果你是准大二，可能会遇到一些新概念——但每个概念我都会用你能理解的方式解释。

### 8.1 问题到底是什么？

一首歌的音频在电脑里是一个一维数组：

```
[0.12, 0.25, 0.31, 0.18, -0.05, -0.22, ...]
```

每个数字代表某个瞬间空气的振动幅度（叫 **采样点**）。CD 音质一秒钟有 44100 个这样的数字。

**混合规则极其简单：** 两种乐器同时演奏时，它们的波形直接相加。

```
混合波形[时刻 t] = 钢琴[时刻 t] + 吉他[时刻 t] + 人声[时刻 t]
```

**所以逆向问题就是：**

> 已知混合波形 y(t)，求 x₁(t)、x₂(t)、x₃(t)…… 使得 y(t) = x₁(t) + x₂(t) + x₃(t) + …

**为什么难？** 一个方程（y）求解多个未知数（x₁、x₂、x₃……），数学上叫"欠定方程组"，有无穷多组解。

这就是你最开始就识别出来的核心问题。

### 8.2 STFT：让计算机"看"音乐

原始波形是一维的，很难直接处理。我们需要一个二维的表示——**频谱图（spectrogram）**。

做法叫 **短时傅里叶变换（Short-Time Fourier Transform, STFT）**：

```
原始波形:  ╱╲╱╲╱╲╱╲╱╲╱╲╱╲╱╲╱╲╱╲
            ↓ 切成小段（约 20ms 一段）
           [──][──][──][──][──]...
            ↓ 对每一段做傅里叶变换
            ↓ （傅里叶：任何信号都可以分解为不同频率的正弦波）
           [▓▓░░▓▒][▒▓▓░░▓][░░▓▒▓]...
            ↓ 拼起来
     频率 ↑
         │ ░░▓▓░░▒▒░░░░  ← 颜色越深=能量越强
         │ ░▒▓▓▓▒▒▒▒░░    这就像一个"声音的照片"
         │ ░░▓▓▓▒▒▒░░░
         │ ░░░▓▓▒▒░░░░
         └────────────→ 时间
```

**关键数字：**
- 采样率 22050 Hz → 每秒 22050 个采样点
- 窗口大小 1024 个采样点 → 约 46ms
- 相邻窗口重叠 50% → 每秒约 86 个窗口（帧）
- 频率分辨率 513 个 bins（0Hz ~ 11025Hz）

所以一首 5 分钟的歌，STFT 后得到一个形状为 **(513, ~26000)** 的二维数组——频率 × 时间。

**为什么 STFT 对分离这么重要？** 因为在频谱图上，不同乐器通常占据不同的频率区域：

```
频率
 ↑   小提琴           ← 高频区
 │      ░░▒▓▓▒░░
 │    ░░▒▓▓▓▓▒░░
 │      ░▒▓▓▓▒░      ← 中频区（大部分乐器在这里打架）
 │    ░░▒▒▓▓▒▒░░
 │   ░░▒▒▓▓▓▒▒░░░
 │  ░▓▓▓▓▓▓▓▓▓▓▓░░   ← 低频区（贝斯、大鼓）
 └─────────────────→ 时间
```

**但问题来了：** 钢琴和小提琴在弹同一个音时，它们的频率是**完全重叠**的。光靠频率位置分不开，必须靠"音色"的细微差异。

### 8.3 音色是什么？为什么能区分？

两个乐器弹同一个音（比如中央 C，261Hz），波形完全不同：

- **钢琴：** 基频（261Hz）+ 丰富的泛音（522Hz、783Hz、1044Hz……）+ **快速衰减**（弹下去后声音逐渐变小）
- **小提琴：** 同样的频率，但泛音权重不同 + **持续延音**（可以拉很长）+ **颤音**（音高微微抖动）

所以音色 = **泛音结构 + 时间包络 + 演奏法**。

深度学习模型的任务就是学习这些差异。

### 8.4 U-Net 架构详解

U-Net 最初是 2015 年为医学图像分割设计的（把 CT 扫描图里的肿瘤边界画出来）。2017 年被引入声源分离领域，效果非常好。

**名字由来：** 网络结构画出来像字母 "U"：

```
        Input (频谱图)
            │
      ┌─────┴─────┐
      │  Encoder   │    ← 逐步缩小，提取高层特征
      │ (卷积层×4) │
      │            │
      │  conv1 → conv2 → conv3 → conv4
      │    ↓        ↓        ↓        ↓
      │  skip1    skip2    skip3    skip4  ← 这些是跳连
      │    ↑        ↑        ↑        ↑
      │  deconv4 ← deconv3 ← deconv2 ← deconv1
      │ (卷积层×4) │
      │  Decoder   │    ← 逐步放大，恢复细节
      └─────┬─────┘
            │
        Output (掩码)
```

**四个核心组件：**

#### Encoder（编码器）

Encoder 的任务是"理解"输入频谱图的整体结构——哪些地方有能量、能量怎么分布的。

每一层做两件事：
1. **卷积（Convolution）：** 用一个 3×3 的小窗口扫遍整个频谱图，提取局部特征（一个卷积核可能专门检测"横条纹"——也就是持续的音符；另一个检测"竖条纹"——打击乐的瞬态）
2. **下采样（MaxPooling）：** 把图缩小一半，只保留每个区域最强的特征

经过 4 层后，原始的 513×T 频谱图被压缩到大约 32×T/16——尺寸缩小了 16 倍，但特征通道从 1 扩到了几百个。

```python
# 简化示意
encoder_level1:  1 通道 × 513×T  →  16 通道 × 256×T/2
encoder_level2:  16 通道 × 256×T/2  →  32 通道 × 128×T/4
encoder_level3:  32 通道 × 128×T/4  →  64 通道 × 64×T/8
encoder_level4:  64 通道 × 64×T/8  →  128 通道 × 32×T/16
```

#### Bottleneck（瓶颈层）

这是网络最"深"的地方，特征最浓缩。在这里，模型"看到"了整首歌的全局结构——哪里有副歌、乐器是怎么配合的。

我们在这个位置加了 **Transformer 层**（Phase 3 的 U-Net++），让模型能建模长距离依赖（比如 10 秒前的吉他主题在 10 秒后重复了）。

#### Decoder（解码器）

Decoder 的任务是把浓缩的特征"还原"回原始分辨率。每一步：
1. **上采样（Upsampling）：** 把图放大一倍
2. **跳连（Skip Connection）：** 把对应 encoder 层的细节接进来——这是 U-Net 的关键创新
3. **卷积：** 融合 encoder 的细信息和 decoder 的抽象信息

#### Skip Connection（跳连）为什么重要

没有跳连的话，decoder 只能靠瓶颈层的压缩信息还原——就像让你凭记忆画一幅只看了 1 秒钟的画，细节全丢了。

跳连让 decoder 能看到 encoder 在各个分辨率下的"原始笔记"：
- 浅层跳连（level 1-2）：带来精细的时频边界信息
- 深层跳连（level 3-4）：带来语义信息（"这是个钢琴"）

### 8.5 掩码机制（Masking）

U-Net 的输出不是分离后的音频，而是 **掩码（mask）**——和频谱图一样大的二维数组，每个位置的值在 0~1 之间：

```python
# 掩码的含义
mask[i][j] = 0.9  → 这个时频点 90% 的能量属于目标乐器
mask[i][j] = 0.1  → 这个时频点只有 10% 的能量属于目标乐器
```

**分离过程：**

```
混合频谱 M    ───→   U-Net  ───→  钢琴掩码:   0.9  0.1  0.7  ← 值在 0~1
                                   小提琴掩码: 0.1  0.8  0.2
                                   贝斯掩码:   0.0  0.1  0.1

钢琴频谱 = M × 钢琴掩码  （逐元素相乘）
         ↓
         iSTFT（逆短时傅里叶变换）
         ↓
         钢琴波形 ← 最终可听的音频
```

**注意这个细节：** 我们用的是混合音频的**相位**（相位信息从 iSTFT 恢复时需要）。这也是分离质量的瓶颈之一——用混合的相位近似代替了真实乐器相位，会引入微量失真。

### 8.6 Loss 函数：模型怎么学？

模型训练时，需要知道"我做得怎么样"。这个衡量标准叫 Loss。

我们的 Loss 由两部分组成：

#### ① L1 频谱损失

```python
loss_l1 = |预测的钢琴频谱 - 真实的钢琴频谱| 的平均值
```

简单直接——预测的和真实的不一样，就惩罚。

#### ② 时序连续性损失（你的想法！）

```python
loss_tc = (相邻帧掩码的差异)² 的平均值
```

翻译成人话：**"第 5 帧的掩码和第 6 帧的掩码不能差太多。"**

这直接对应于你最初说的：**"相邻时刻的波形形态、音量、音色不会出现突兀跳变。"**

### 8.7 训练过程

训练 = 不断重复以下循环：

```
1. 从数据集中取一批 (混合音频, 真实各乐器音频) 对
2. 把混合音频送进 U-Net → 得到预测掩码
3. 用掩码分离 → 得到预测各乐器频谱
4. 计算 Loss（L1 + 时序连续性）
5. 反向传播（告诉模型"你哪里做错了"）
6. 更新模型参数（让模型做得更好一点点）
7. 回到第 1 步
```

在我们的 Phase 2 训练中：
- 100 个 epoch（完整过一遍数据 = 1 epoch）
- Loss 从 0.028 降到 0.002（93% 的改善）
- 模型参数：194 万个数字，从随机值逐渐变成"会分离乐器"的排列

### 8.8 Demucs 为什么比我们的 U-Net 更好？

我们训的 U-Net 参数量 194 万（Phase 2），Demucs 的参数量约 **8,000 万**，是我们的 **40 倍**。

Demucs 比我们的 U-Net 多了几个关键改进：

| 改进 | 我们的 U-Net | Demucs |
|------|:----------:|:------:|
| 处理域 | 仅频域（STFT） | **时域 + 频域 混合处理** |
| 参数量 | 194 万 | **~8000 万** |
| 时序建模 | CNN（局部） | CNN + **Transformer（全局）** |
| 训练数据 | 4 段合成音频 | **MUSDB18: 150 首真实多轨录音** |
| 多尺度 | 单一尺度 | **多时间尺度同时处理** |

Demucs 的 Hybrid 架构同时处理：
- **时域分支：** 直接在原始波形上操作，保留相位信息（我们的方法用了混合相位，有损失）
- **频域分支：** 在 STFT 频谱上操作，利用频率的稀疏性

两个分支的输出在最终层融合。这比单独用频域好，因为时域分支能补偿频域分支丢失的相位信息。

### 8.9 为什么构想一成功了而构想二还没做好？

这两种方法的本质区别可以用一个类比说明：

| | 构想一（掩码法） | 构想二（生成式） |
|---|---|---|
| 类比 | 从合影里把每个人"抠"出来 | 听一遍合影的对话，然后**自己演一遍**每个人说的话 |
| 需要的技能 | 识别边界（边缘检测） | **听懂语义 + 学会模仿** |
| 训练数据要求 | 需要"合影 + 单人照"的配对 | 需要"合影 + 单人照 + 每个人说话的录音" |
| 合成环节 | **不需要**（直接从原图抠） | 需要**高质量的语音合成器** |
| 瓶颈 | 边界模糊时抠不干净 | 合成器音质不行 → 怎么听都不像 |

**构想二的想法本身没错，但它对"合成器质量"的依赖比我们预期的要高很多。** 如果没有一个真实的 SoundFont（高质量的乐器采样库），用简单的 sine wave 合成器永远做不出逼真的效果。

这就像要你**用计算器弹奏《月光奏鸣曲》**——旋律和节奏都对，但音色永远是"哔哔"声。这不是演奏者的错，是乐器的问题。
